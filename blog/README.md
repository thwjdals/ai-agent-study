# 글·발표 (대외 검증, 상시)

내가 말하는 게 아니라 제3자가 확인해 주는 증거만 쌓는다. 별도 기간이 아니라 전 기간 병행한다.

만든 걸 글이나 발표로 풀고, **거기서 막히는 질문을 다음 학습 주제로 삼는다.**

## 예정 글

| 단계 | 글 |
| --- | --- |
| 2단계 | 수치로 본 RAG 설정 비교 |
| 3단계 | 로컬 모델로 해 본 에이전트 루프 엔지니어링 |
| 캡스톤 | 평가 수치가 붙은 에이전트 하네스 소개 |

## 쓰는 법

- 초안은 `drafts/`, 발행한 글은 `published/`에 원문을 남기고 표에 링크를 붙인다.
- 실험 글은 수치를 본문에 싣고 재현 스크립트 위치를 같이 적는다. 수치 없는 "좋아졌다"는 안 쓴다.
- 발행하면 [`../CURRICULUM.md`](../CURRICULUM.md#대외-검증-상시)의 해당 졸업 기준을 체크한다.

## 발표·OSS

| 활동 | 시작 | 목표 |
| --- | --- | --- |
| OSS 기여 | 3단계 | 매달 PR 1개. 문서·테스트 수정 → 기능 기여 |
| 기여 대상 후보 | 3단계 | MCP SDK·서버, LangGraph, Ollama 주변 도구 |
| 내 도구 운영 | 3단계 | MCP 서버 이슈·피드백 대응 기록 |
| 발표 | 3단계 이후 | 사내 공유 → 외부 밋업 → PyCon KR 같은 CFP |

OSS PR과 발표 이력은 `record.md`에 날짜·링크·결과로 한 줄씩 남긴다.
